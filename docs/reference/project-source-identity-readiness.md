# #116-C readiness: trusted Main identity and source registration

Status: **design and future test contract only; no producer, production identity or grant activated**. This document complements [the exact authorization contract](./project-source-authorization.md), [B1 proposal at its reviewed starting SHA](https://github.com/Guan21/cc-orca/blob/b38be004e89f5bf0f0589d04a79cdca4614ec5e0/docs/reference/project-source-trust-b1.md) and [B2 infrastructure](./project-source-authorization-b2.md). Security-owner approval of this design and its implementation is still required. The native exclusive file-create completion is a **candidate, NOT APPROVED**. Project Map remains Source Unavailable.

## 1. Reader derivation and current evidence

Main must identify the actual Electron sender, its currently authorized main frame, and the current application/document session before resolving an opaque principal handle. Renderer IDs, usernames, URLs and claimed principal strings are selection inputs, never authentication.

| Existing Main surface                              | Demonstrated behavior                                                                                                                                    | Required additional proof                                                                                                                                                                                                                                    |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/main/window/createMainWindow.ts`              | Creates the desktop BrowserWindow, records its WebContents ID for UI operations, and enables context isolation, sandboxing and disabled Node integration | Register the exact WebContents object and permitted document in a dedicated source-reader record; window membership alone does not grant access                                                                                                              |
| `src/main/ipc/ui.ts`                               | Tracks a trusted renderer ID; some UI operations use `isTrustedUIRenderer`; packaged fallback denies without registration                                | Its development URL/origin fallback when the ID is absent is insufficient for source access. A missing registered reader must deny in all modes; do not inherit that fallback                                                                                |
| `src/main/ipc/runtime.ts`                          | Selected runtime handlers compare `event.senderFrame` to `event.sender.mainFrame`                                                                        | Apply an independently reviewed registered-sender and document-generation check before each future source operation and again before delivery. The `desktop-ipc` token and renderer labels are internal routing values, not authenticated project principals |
| `src/main/ipc/desktop-runtime-sender-lifecycle.ts` | Main mints connection generations and aborts subscriptions on committed navigation, renderer loss and destruction                                        | It retires on `did-navigate`, not navigation start. A source-reader lifecycle must fence the departing document before asynchronous completion and invalidate on reload, navigation, crash and destruction                                                   |
| `src/main/window/renderer-document-navigation.ts`  | Tracks main-document navigation starts and committed generations, including blocked-navigation recovery                                                  | This is an existing lifecycle pattern, not a source principal authenticator. Source revocation must never revive an old ticket if a blocked navigation leaves the document intact                                                                            |
| `src/main/window/privileged-window-navigation.ts`  | Blocks foreign privileged-document navigation and denies new windows                                                                                     | Navigation policy must be reviewed alongside the actual preload, window creation and frame validation; document origin alone is insufficient                                                                                                                 |

A future Main-owned application session needs an independently minted namespace and a document generation bound to the registered object/frame. B2 accepts installation/session IDs and principal inventories through trusted constructor inputs; it does not derive them from production records. Persisted profile identifiers must not silently become installation attestation or session authority.

Personal session identity means a verified local application reader eligible for reviewed local consent. Enterprise authenticated identity additionally requires an approved enterprise authentication and policy authority. Neither follows from an OS username, GitHub login, project membership, profile name or IPC caller claim. `src/main/orca-profiles/profile-cloud-auth-status.ts` projects configured profile/cloud session status and capabilities; it is not an implemented Project Source enterprise policy issuer.

## 2. Required Main-owned records and reconciliation

The future composition root must build immutable source bindings from independently reconciled records, rather than accepting a renderer-supplied scope. The required tuple remains the one in `src/shared/project-source/project-source-access.ts`: installation, session, principal, producer, source, project, setup, repository, workspace kind/ID, worktree identity, execution host/realm, incarnation, registration revision and policy epoch.

| Records / code                                                                                   | What may be reused                                                                          | What must not be inferred                                                                                                                         |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Store project, repository and ProjectHostSetup records; `src/shared/project-types.ts`            | Exact project/setup/repository linkage and setup lifecycle                                  | `setupState: ready` is setup status, not source attachment or successful observation                                                              |
| `src/shared/project-host-setup-lookup.ts`                                                        | Existing setup lookup behavior                                                              | Its repo-only and synthesized projection fallbacks cannot prove exact host-qualified source ownership                                             |
| `src/main/ipc/worktrees/listing/worktree-host-ownership.ts`                                      | Rejects malformed/contradictory repo ownership and offers exact owner/current-record checks | Legacy absence of a host defaults to local there; a source registrar must independently establish native locality and reject unresolved ownership |
| Worktree inventory and Main Store worktree metadata                                              | Exact known worktree and captured-current checks                                            | A path or event worktree label is not a registered worktree identity                                                                              |
| `src/shared/folder-workspace-types.ts`                                                           | Exact folder workspace ID and explicit folder scope                                         | The host stamp is documented as renderer-owned; it cannot authenticate native execution. Missing legacy creator provenance means unknown origin   |
| `src/main/ipc/registered-worktree-roots-cache.ts`; `src/main/ipc/filesystem-path-containment.ts` | Registered-root revisions, canonicalization and containment patterns                        | Broad allowed roots, textual cache membership or a one-time realpath do not prove stable root ownership through a later operation                 |
| `src/main/ipc/filesystem-allowed-roots.ts`                                                       | Existing filesystem access routing                                                          | Filtering repos by `connectionId` alone does not attest execution realm, paired-runtime exclusion or source permission                            |

Require a unique, noncontradictory exact setup/repository/workspace owner. Folder sources use `kind: folder-workspace` with an exact workspace/repository and explicit `worktreeId: null`; Git sources use `kind: git-worktree` with a known exact nonempty worktree ID. Missing fields never mean null or wider scope. Unknown hosts deny rather than fall back to local. Windows Main must independently distinguish native execution from WSL, including workspace mirrors and per-project runtime preferences. B2 rejects Corporate, SSH, WSL and paired-runtime registrations; these exclusions remain until separately approved.

## 3. Producer and registration lifecycle

An approved Main composition root owns the producer instance and privately holds its opaque `ProducerHandle`. It must authenticate the producer implementation and incarnation independently of `event.source`, event IDs, metadata or workspace content. `ProjectSourceRegistry` currently mints fresh opaque symbols, UUID incarnations and registration revisions from an injected immutable catalog. Catalog acceptance is a trust assumption, not attestation.

The future lifecycle is: verify records/root/locality and approval; register a new exact immutable binding; attach the authenticated current producer; enter loading; establish successful observation separately from read permission; publish an authorized empty or ready snapshot only while the attachment, observation and grant remain current. Lifecycle failure yields error, stale/disconnected or unavailable as appropriate, without exposing earlier events as fresh. Event timestamps are producer content, not a freshness clock. Main observation freshness must use trustworthy Main lifecycle evidence and an injected monotonic clock with an approved expiry policy.

Replacement, root/setup mapping change, producer restart, reader session end, policy epoch change or disposal must synchronously invalidate the old handle, tickets, pending batches, observations and availability before a new registration is used. B2 registry replacement invalidates the former handle; disposal of the actual producer instance remains the future composition owner's responsibility. Same-scope reissue uses a new trusted lease generation and cannot rehabilitate old work. Lookup of a registration never issues a grant. A read grant alone never attaches a producer or establishes an empty source.

## 4. Separate authorization modes

**Personal Local Mode:** explicit, reviewed user consent is required for the exact local project/setup/repository/workspace/worktree/native-host scope and the separate ingest/read operations. The consent design must specify the Main-authenticated reader, wording, lifetime, withdrawal, scope changes, storage and session boundaries. Only after that design and issuer are approved may Main issue narrow session grants. Existing filesystem access, personal profile state, agent trust settings and OS ownership do not substitute for consent. No production personal grant is created by B2.

**Corporate Mode:** requires an enterprise-approved authenticated principal and policy authority that explicitly approves source registration and operations for the exact enterprise scope. Define tenant/group membership, policy ownership, freshness, logout and administrative revocation before activation. Personal consent, OS username, GitHub login and renderer/IPC claims cannot grant Corporate access. Corporate registrations remain disabled until approved authority is implemented. Data permission and Corporate network approval are separate gates; this slice enables neither network communication nor credential storage.

## 5. Mandatory trusted revocation notification

The authority owning immutable lease records must deliver `ProjectSourceLeases.revoke(leaseId)` synchronously as part of explicit revocation, whether it removes the record before or after notification, before yielding control or accepting replacement work. Use unique IDs per issuance within the authority namespace. If an ID is reused, revocation must complete before reissue and delayed notifications must be excluded: the string-only notification cannot distinguish old and new generations and conservatively revokes every matching current/accepted registration. A reissued grant requires a fresh immutable record/generation. Main retains bounded associations for accepted grants even after tickets are released, so record removal does not prevent locating affected registration state. Registration invalidation frees those associations; exhaustion refuses a new operation. A repeated/unknown notification is safe and never creates authority.

Notification invalidates affected registrations and all their tickets, pending batches, retained observations and availability. Purging the whole registration is deliberately conservative: another principal's grant on that source does not preserve revoked source observations. Unrelated registrations remain isolated. Source/session/policy lifecycle owners must likewise notify/invalidate on producer replacement, termination, session end and policy epoch change. Validate at admission, commit, snapshot creation and final asynchronous delivery; already captured copies cannot be treated as authorized delivery after revocation.

Silent removal from an external lookup cannot be detected instantaneously without a lifecycle signal. Access checks fail closed on observed withdrawal or expiry, but this is not a promise of immediate passive detection. No polling/timer is added. The future runtime owner must document notification delivery, ordering and failure handling; loss of the authority must fail closed without claiming a source or remote process has exited.

## 6. Future IPC and preload security review

No channel or preload export is added here. Before any future bridge, review the complete IPC/preload/CLI/RPC inventory and all call sites, including alternate windows, guests, subframes, dev origins, reload recovery and frame reuse. Independently bind the sender object, registered current main frame, Main document/session generation and principal; never accept grants, authenticated claims or opaque authority tokens from payloads. Renderer may request an exact selection but Main resolves and reauthorizes it.

Bound payloads before recursive parsing. Keep ingest, snapshot and evidence-content permissions separate. Bind asynchronous replies to the captured reader, complete scope and current generation, revalidate immediately before send, and abort on lifecycle invalidation. Prevent broadcast or reused subscription IDs from crossing readers. No evidence-content endpoint exists in B2; an `evidenceRef` is schema-validated inert event content, not an access capability or proof of secret redaction. Any future content lookup requires a separate approved authorization/redaction design.

## 7. Native root/locality and TOCTOU proof obligations

The candidate exclusive file-create completion in `src/main/runtime/runtime-file-commands-write-file-explorer-file.ts` awaits `writeFile` with `flag: 'wx'` after existing filesystem authorization. B1 proposes observing that narrow completion, never authorship, code correctness or task/test completion. It must prove that the operation was initiated and completed by an approved Main-owned native producer in the exact registered root. It cannot be inferred from a watcher notification or fabricated DevelopmentEvent. Validate the captured root/setup/workspace and native realm before execution and revalidate them before admitting success.

Security review must address symlink/junction/reparse-point swaps, root replacement/removal, path aliases and case, Windows drive/UNC/network paths, WSL/remote mounts, ancestor changes, hard links, concurrent file replacement and exclusive-create semantics on all supported platforms. `normalizeExistingPath` preserves an absent textual path on ENOENT; this is not proof that a future created file stays inside a stable canonical root. Existing realpath/containment helpers do not by themselves close the check/use race. Require an approved handle-relative or equivalent validated strategy, with adversarial tests and a stated residual same-user OS/Main compromise boundary, before accepting the candidate. Collect no raw conversation, transcript, credential or secret-bearing evidence.

## 8. Decisions requiring security-owner approval

Approve the actual producer and provenance boundary; registered desktop/document session derivation; installation namespace ownership; exact record reconciliation and native-root proof; personal consent and issuer; enterprise authentication/policy authority; grant durations and offline/suspend behavior; availability/freshness transitions; explicit revocation notification reliability; limits and retention; and the complete future IPC/preload inventory. No reviewed document alone establishes these runtime guarantees.

## 9. Future negative integration-test matrix

These are required future integration cases, not claims that B2 tests exercise a production connector.

| Attack / lifecycle case                                                                                      | Required result                                                                                             |
| ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| Unregistered WebContents, guest/subframe, foreign document, URL-only match or missing reader registry        | Deny before source access; no grants or data                                                                |
| Departing/replaced main frame, reload, navigation start, renderer crash/destruction or reused WebContents ID | Invalidate reader generation; no old asynchronous delivery                                                  |
| Renderer-supplied principal, grant, producer label, attachment flag or fabricated event                      | Never establishes identity, permission or availability                                                      |
| No producer, registered but unattached source, read-only grant without successful observation                | Unavailable, never authorized-empty                                                                         |
| Explicit lease revoke before/after record removal; multiple pending commits/reads; repeated or unknown ID    | Old work rejects; relevant observations/availability/evidence refs inaccessible; unrelated source preserved |
| Same-scope reissue, producer replacement, policy epoch/session change or clock failure                       | Old tickets never revive; fresh authority/attachment required                                               |
| Project/principal/repository/worktree/folder/host/realm switch during a deferred read                        | No prior scope events or selection delivered                                                                |
| Ambiguous setup, duplicate repo owners, missing worktree, malformed host or contradictory connection         | Deny without fallback or inferred local authority                                                           |
| Native claim over WSL mirror, SSH, paired runtime, UNC/network or unresolved root                            | Deny unless separately approved locality proof applies                                                      |
| Junction/symlink/root swap between validation and exclusive-create completion                                | No admitted success without stable approved ownership proof                                                 |
| Personal consent used for Corporate; GitHub/OS/profile identity used as policy                               | Corporate denies; no network or grant activation                                                            |
| Oversized/deep replay, mixed scope/incarnation, conflicting duplicate or concurrent version mismatch         | Bound before recursive parsing; atomic rejection; no partial evidence                                       |
| Source failure/disconnection, authority outage or expired freshness                                          | Never report retained observations as fresh or assume process death                                         |
| Evidence reference presented as a content capability or alternate endpoint request                           | No content returned without separately reviewed authority                                                   |

Run Electron integration checks with `ORCA_BACKGROUND_LAUNCH=1`, hidden renderer CDP validation and no desktop focus changes; native visible/focus acceptance belongs on an isolated display or CI. The known-unresponsive Windows QA VM is not a prerequisite for this unwired slice.

## 10. Producer activation criteria

Activation requires recorded security-owner approval of the chosen producer and both identity/authorization modes it supports; implemented and independently verified exact Main record/root/realm derivation; reviewed personal consent or approved enterprise authority; trustworthy source lifecycle and freshness; reliable synchronous revocation notifications; bounded atomic ingest/read and final-delivery authorization; reviewed IPC/preload inventory; and passing negative integration tests at the proposed activation SHA. Corporate remains disabled without its separate authority, even if personal local mode is later approved. Native exclusive file-create completion remains NOT APPROVED until its proof obligations are resolved. No runtime activation switch, production source, Project Map wiring, new endpoint, network access or background polling is introduced by this document.
